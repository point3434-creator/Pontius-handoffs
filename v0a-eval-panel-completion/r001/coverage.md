# Deferred implementation coverage and evidence limits

Read only after the reviewer writes and hashes an independent invariant inventory.
This is an implementer map, not a verdict. NEW-SURFACE, Tier C, steps 4-7.

1. Decision to plan: completion validate binds the actual retained capacity and
   preflight SHA-256s, decision SHA-256, H=1081, board and measured pool order.
   Full solve admits exactly 600 s / 2048 MiB. Test subsets cannot use these
   prerequisites or claim the full pool. Admission-only receipt reads the actual
   inputs without invoking a phase; changed count, seed and envelope are refused.
2. Plan to worker: existing immutable AdmittedPlan and supervised worker remain
   the only execution entry. Schemas separate capacity/preflight from completion;
   solve/export/agreement never invoke one another. Each export/agreement input
   binds absolute path and SHA-256. The existing bounded OwnedInput reads bytes.
3. Worker to teacher: solve calls existing hand_totals once per admitted hero in
   the fixed permutation prefix. Per-hand totals and untraced cost are emitted
   immediately. Missing rows cannot produce a complete teacher. The existing
   kernel settlement and singleton reference arithmetic were not modified.
4. Tie to reference: first exact tie with wins+losses>0 invokes the sealed
   singleton reference, both forced values and best_response, then the existing
   lattice comparison. Parent reconciliation requires that first tie's passed
   comparison. No full-pool solve occurred; discovery/absence of such a tie is
   still an operational result, not established by these subset tests.
5. Rows to immutable bytes: canonical ASCII JSON binds fixed root, opponent law,
   ordered universe, H and ordered value/action rows. Parsing refuses duplicate
   keys, changed domain, noncanonical spelling/bytes, incomplete H and invalid
   totals/actions. Optional outcome/work fields, if supplied, must be consistent.
   Validation proves row consistency; it does not independently solve a policy.
6. Teacher to export: export consumes bound producer bytes and completed result,
   verifies matching scope and artifact identities, and never calls hand_totals.
   Two encodes must match. Source ID is t1:<teacher SHA-256>. Real decode compares
   every key/action; actual encoded bytes must fit the existing artifact cap.
7. Export to membership: validate_membership enumerates all 1081 root hands,
   independently calls PreparedBlueprint.action_for and BlueprintProvider.propose,
   checks complete entries, actions, reason labels and decision identity. The
   four-row subset control yields four hits and 1077 complement defaults. These
   are library/provider checks and cannot establish blueprint-v1 host behavior.
8. Bank to witnesses: fixed finite increasing seeds and ordered indices 0..15;
   holdout seed range disjoint and reserved. All twelve dealer private cards stay
   unchanged. Only board collisions reject draws. First accepted hero witness
   wins; collisions and unused draws remain in order. Each draw streams before
   the final census. Missing H coverage fails before any host attempt. The IID
   union-bound estimate is explicitly an approximation, not a coverage guarantee.
9. Witness to Session: actual Session prepares one hand at a time at inherited
   run root and context. Cached host Admission still verifies each schedule and
   artifact. The host/session/dealer and runtime source are unchanged. Input files
   are reused inside the owned run directory; retained captures preserve each
   attempt's witness, wire digest, actual actions, settlement and frame stream.
10. Transport to outcome: classify reads outer Session, hand entry and nested
    host result before NDJSON. Failed/truncated/incomplete outcomes are excluded,
    including nullable pre-decision failure envelopes. Real transport failure is
    triggered only after an actual send through the native connection. The test
    retains actual cleanup and failed Session behavior, not a fabricated capture.
11. Frames to replay: complete strict NDJSON, event/action pairing, real v1 record
    shape, timing, hand_result and session_result closure. Kernel replay checks
    applied actions, cards/state hashes, event count and settlement. Showdown
    publication counts separately from street advancement: the real CHECK stream
    exposed an error shared by the original fixtures. The fix passes that stream.
12. Identity to observation: ready/host/Session source commit and blueprint IDs
    reconcile; child ID derives from outer session ID and hand ordinal. The ready
    source-manifest SHA has no independent outer envelope field. Its value is
    checked by unchanged host admission; the classifier checks its format only.
13. Outcome to agreement: chip eligibility precedes agreement. Prefix-diverged
    baseline fixtures retain chips, including fold and early all-in settlements.
    Eligible v1 river records are checked against a fresh action_for lookup and
    teacher, including selection_reason. The v1 record has no delivery_status.
    Changing only a real CHECK hit's reason to passive_default is disagreement
    while the settled chip outcome stays eligible. CHECK/default actions alone
    cannot establish a hit. Unknown reasons are disagreements, not missing chips.
14. Attempt to parent: explicit scheduled ordinal/hand/label/witness precedes the
    real session. Partial accounting requires each observed outcome to match it.
    Completed primary hits, missing pool hands, scheduled-but-missing outcomes,
    unsupported, disagreement and excluded remain distinct. Parent refuses missing
    census rows, duplicate observations and incomplete phase summaries. A control
    cannot inflate the production H count. Real controls include proper-subset
    off-pool, CHECK-hit and changed-stack zero-hit sessions with distinct artifacts.
15. Publication to result: artifact identity is bound before rename; failed rename
    retains base64/pending identity, successful rename followed by interruption
    reconciles published bytes. Existing native worker ownership/resource cleanup
    remains in force. The real CLI two-hand solve/export/agreement chain checks
    three bound producer results and exactly one journal row per invocation,
    with no per-hand journal rows. SHA mismatch refuses producer input.

## Evidence and boundaries

Focused suites: existing eval_bridge and eval_panel_tool plus eval_export,
eval_agreement and eval_completion_tool, through registered tests/test_pontius.py.
Final receipts must name the exact frozen candidate and source_verified=true.
ResourceWarning and pytest unraisable warnings are errors. Ruff and raw-blob
hygiene/whole-slice counts are separate checks. Fixtures are labeled; actual
worker, native host, codec, provider and journal boundaries remain real where
those boundaries are claimed. No optional GPU environment is used.

Initial availability and later fault RED checks ran during implementation.
Some initial outputs remain only in tool history; no raw receipt is invented.
Retained classifier RED files and a separate provenance note state which source
was dirty, which defect was observed and what the final frozen gate supersedes.
These implementer checks are not cold reviews and carry no CLEAN verdict.

Limitations: no retained full-H solve, nonzero-tie census, full-H host agreement,
holdout, paired chip estimand, confidence interval, calibration or strength claim.
The subset actual host check is not a full-population agreement certificate.
Baseline divergence fixtures establish classifier handling, not a retained
baseline host campaign. Full resource admission is tested by read-only input
validation; resource adequacy remains the controller's measured decision.

Two independent cold passes precede broad tests and ceremonial adoption. Later
solve/export/agreement need separate concrete plans and one-shot authorizations.
