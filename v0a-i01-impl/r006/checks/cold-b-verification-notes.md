## B1 — invented clock cause after a dead-witness refusal

The diagnostic first records the read count when the real settlement oracle is
entered on a successful run: read 134. It then runs a new host with one source
failure at that position and an oracle that calls the same real MonotonicWitness.
The entry seam records the genuine cause, then yields into the body. The failed
witness refuses the body's call without consulting the source (clock.py:47-48).
The new owner's class-only handler at runtime.py:414-416 records that refusal as
another genuine cause. Expected versus observed:

- reversed: [clock_reversed] versus [clock_reversed, clock_invalid]
- invalid: [clock_invalid] versus [clock_invalid, clock_invalid]
- source exception: [clock_invalid] versus [clock_invalid, clock_invalid]

Each run has exactly one independent source fault and exactly 134 source reads.
Both interpreters reproduce all three discrepancies. Four already accepted
mailbox actions and four full decisions survive; host success remains false.
The material defect is false typed-cause accounting, not an accidental success.
The required correction is to retain origin/retention knowledge across entry,
body, and exit so an already-retained refusal is not journalled as a new cause,
while separate genuine equal-code faults remain distinct. Enum deduplication is
not the required behavior and would lose real multiplicity.

## B2 — fallible formatting escapes the owner

Through the supported settlement_oracle callback, raise a ValueError subclass
whose __str__ raises RuntimeError. Runtime.py:415 records settlement_mismatch,
then line 416 evaluates str(error) before constructing OperationFailed. That
formatting RuntimeError escapes ReplayHost.run, whose new handler catches only
OperationFailed. No ReplayOutcome/host receipt is returned. Both interpreters
reproduce this. The publication owner repeats the same fallible operation at
runtime.py:429; the executable reproduction is the settlement path.

Required behavior: constructing the owned-failure signal must not run fallible
callback formatting that bypasses receipt containment. Use of a constant message
or another non-failing representation is an advisory technique, not a separately
binding architecture requirement. This case has lower expected frequency than
B1 but directly violates the explicit host-exception containment contract.
