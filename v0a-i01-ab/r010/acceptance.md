C required outcomes:

- Exactly the six declared v0a origins; no blanket namespace admission. External
  internal-module dependencies follow ADR-0485. Only replay may use river and
  SixSeatHoldemDeal; non-host v0a must not import replay or the complete-deal type.
  Cover absolute/relative imports, aliases, qualified and deferred symbol use,
  wildcard import, initializer origins and malformed syntax. Comments/strings and
  legal visible-state use remain accepted. This is trusted component separation,
  not a malicious-Python introspection sandbox.
- Legacy outgoing edges, SCC policy, baseline bytes and sealed kernels are
  unchanged. Baseline blob5fe6ee47f3380b65887b528efef05b72c8e6ac0a remains pinned.
- Static helper-call analysis must respect actual source-ordered callable identity,
  descriptor binding and Python positional/default/keyword semantics. Legal defaulted
  receivers, static all-default signatures and positional-only receivers must not
  crash or mis-bind. A historical name or receiver spelling alone is not authority
  for the current callable. All supported binding scopes and local/imported helper
  paths must obey this rule. Callee selection, argument evaluation, definition-time
  defaults and later closure lookup must preserve their Python ordering.
- Unknown callable/member provenance, receiver context, invalid arguments or
  unsupported mutation/escape must remain explicitly blocked even if the body has
  literal sink argv. Actually dead calls remain nonexecuting. A proved failed lookup
  preserves its exact exception successor and has no helper-body rows; an absent
  snapshot alone does not establish that proof. Preserve direct unittest-entry preflight, existing
  lawful nested/cross-file behavior and the analyzer's finite fail-closed limits.
  Analysis must not execute inspected sensitive source, silently discard unresolved
  sensitive paths, guess capability authority, or bypass its work budget. No general
  Python heap or reflection support is required; unsupported behavior must refuse.
- Register the five new v0a suites in the current stabilization inventory. Preserve
  every existing entry assignment. Derive inventory and profile bytes ordinarily,
  bind the final combined corpus, and mechanically refresh only affected census
  expectations. No baseline or capability approval/digest grants may change.
- CI adds the five clone-safe CPU suites without removing/demoting any existing
  hard gate. They must remain reachable after earlier failures unless canceled.
- Both actual3.11.15 and3.14.6 must pass focused checks under the isolated snapshot
  procedure. No optional GPU dependency becomes required. Generated --check must
  pass without mutation; a changed source byte is a new candidate.

Source-point authority must remain complete when an owner appears only in a
captured default, closure or receiver. A semantically irrelevant owner read must
not determine whether an unsafe reached effect is refused. Forwarding and opaque
execution/escape must preserve or explicitly refuse relevant callable authority;
absence of discovered proof is not proof that no relevant effect exists.
Creating a deferred computation does not execute its body. Supported consumption,
unknown escape and proved nonexecution must retain their distinct outcomes.
These clarify the existing identity/effect contract, not a requirement for a
general callback interpreter or new capability support.

Callable construction must retain source-point default/decorator authority and
class definition ordering. Relevant unresolved annotation effects may refuse under
the declared portable policy; deferred annotations must not be reported as having
executed. Literal, bare-type, proved readonly and dormant controls remain lawful.
