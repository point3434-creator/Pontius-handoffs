## Disposition: static class scope plus existing value absence

Add a construction-time immutable class scope with local_names, global_names, nonlocal_names and read/free classifications to _ClassFrame. Reuse/extend the existing scoped visitor; do not call function-only _lexical_binding_scope(ClassDef), which reads args. Class-local membership is a syntactic scope fact, independent of whether its binding statement runs. Keep class bodies separate from nested function/class bodies while visiting eager metadata in its real scope.

At class entry, keep bindings reset except proved explicitly declared class nonlocal destinations. For EVERY statically class-local name, raw-mask any inherited projection with the existing unbound value before body execution. Actual local stores replace that slot; deletion restores local absence. Existing maybe_unbound represents branch-local presence uncertainty. No lexical token, plain-int pseudo-cell, bindings[name]=(), or separate dynamic shadow set is needed for class locals. Their only ownership is this class name namespace.

Python's scope distinction matters: a free class-body name can resolve to an enclosing function cell; a name bound in the class block is class-local throughout the block, and when locally absent its fallback is the module namespace. Deletion counts as a binding for scope analysis. A class local therefore must not reveal an enclosing same-spelled function cell after deletion, before its first assignment, or on a branch where its assignment did not run. These are language rules, not value-identity heuristics. [Python 3.11 execution model](https://docs.python.org/3.11/reference/executionmodel.html#resolution-of-names)

Class-local names do not become free destinations of methods or comprehension bodies. The outermost comprehension iterable, function defaults/decorators and nested-class headers still evaluate in their actual enclosing context. Modern annotation/type-parameter scopes have additional rules outside this bounded floor-compatible change; keep unsupported cases conservative. [Python 3.14 execution model](https://docs.python.org/3.14/reference/executionmodel.html#resolution-of-names)

Why not the alternatives: an empty bindings tuple union cannot distinguish definite local presence from absence on another branch. An unproved class-local cell would need explicit absent alternatives too, add allocations in the disabled prepass, and mix namespace bookkeeping with destination identities. Static local-name membership plus existing projected absence already provides the needed distinctions in both authority modes. If a future operation can dynamically introduce arbitrary class names, it needs its existing explicit dynamic-namespace refusal; it may not pretend the static set is complete for that operation.

## Exact APIs and transfer rules

- _class_name_route(name, frame): returns class_local, declared_nonlocal, declared_global, free_lexical, or ordinary_global. This classification never inspects a FlowValue's equality, identity or sensitivity. It uses own class declarations and the scope-aware enclosing activation view, not the outer function's declarations applied to the class.
- _class_read_name(node, state): a definite class-local value comes from its projected slot. For unbound/maybe_unbound, preserve the module-fallback alternative; do not raise an enclosing-local UnboundLocalError or discard absence and use only present alternatives. Use established defining-module/builtin projections where valid. If that fallback is unrepresented, return a conservative unresolved value/obligation which reaches the sensitive consumer, or emit an explicit blocker at that reached consumption. Never substitute an enclosing local or silently choose a harmless branch. Do not overwrite the local slot with its fallback result: it remains locally absent.
- Free lexical reads resolve frame ownership against CURRENT successor cells. _refresh_class_free_projection(state) raw-hydrates only those free names, excluding every class-local/global declaration; it preserves unknown/unbound and retained authority. Apply it before class semantic read/proof/snapshot boundaries and after relevant helper adoption/join. Existing ordinary captured global placeholders retain their established global projections; they are not automatically refused.
- _class_store_name / _class_delete_name: class-local writes affect only the projected local slot, with no lexical binding tuple. Declared nonlocal writes use the exact existing enclosing activation tuple only when the shared ownership proof succeeds; otherwise emit the explicit unresolved-destination refusal. Direct declared global writes/deletes keep conservative module-write refusal and must not be silently modeled as class-local or caller-local writes. This includes imports and def/class/handler/pattern binding forms subject to an own declaration, not only Assign.
- Class-local delete checks local presence only. An absent local deletion raises NameError; it does not delete or consult an outer cell/global binding. A successful delete marks local absence. A maybe-present delete retains existing exceptional and surviving possibilities without inventing new branch correlation. Later reads use the class-local global fallback rule above.
- A declared-global READ is distinct from a module WRITE: use established defining-module read behavior, never a same-spelled caller local. An unproved placeholder forbids nonlocal guard relief but is not, by itself, an incomplete capture or a reason to refuse every imported/module read. Preserve negative evidence only where a consumed contract actually requires it. Missing required nonlocal/retained-store alternatives cannot be erased by join; ordinary global projections must not acquire blanket helper_refusal.

The class namespace projection is not a read-through cache for all fallback values. Only free lexical slots may be refreshed from cells. Local absence stays explicit so subsequent assignment, deletion and joins remain correct. Name-read services and any read-only merged view used for aliases must not publish fallback values as local stores. Captured method defaults retain their already evaluated values; method-body captures skip this local namespace.

All syntactic Name-binding forms found in the scoped visitor are covered above: Store/Del targets, NamedExpr, for/with/except/match, imports, definitions and annotation-only classification. Global/Nonlocal nodes establish static own-scope routing; they do not perform a write themselves. Ordinary attribute/subscript/reflection stores are not Name rebinding, even when implementation rewrites a root projection afterward.

Fork preserves the immutable frame and projected local absence/value. Join uses existing _merge_legacy_flow_values 13492-13510: present plus absent becomes maybe_unbound; absence must not be converted into a globally resolved value before this merge. Delete/handler cleanup retain absence on surviving states. A branch example `if flag: armed=False; if armed: ...` has a class-local present/absent join; its absent side uses module fallback, not the enclosing function cell. This addendum makes no new promise to recover correlations already merged by existing flow.

A class exit projects only the outer continuation and current cell/object effects, so masks, local values and handler aliases do not escape. Explicit supported nonlocal cell writes do survive. A reached unsupported global/nonlocal write emits a standalone public refusal that survives class exit, including an exceptional exit; a dropped projected write plus no blocker is forbidden.
