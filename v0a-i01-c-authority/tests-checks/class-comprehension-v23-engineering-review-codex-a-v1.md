## Three unexecuted source concerns

These are source-proved transformations and unexecuted public scenarios, not additional demonstrated product failures.

1. **Target receiver/index loads are allocated as implicit locals.** At 15579–15587 every ast.Name anywhere under each comprehension target is added to targets, projected unbound, and allocated as a new local cell. A target such as owner._launch contains a Load of owner, not a local binding of owner; box[index] likewise reads receiver and index. _assign reaches _helper_namespace_store, which evaluates an attribute receiver before its protected-write checks (19030–19036, 22016). With the invented local scope, an unbound receiver produces UnboundLocalError (16802 onward, 20067 onward). A surrounding except NameError can catch that fabricated pre-store failure and leave a clean continuation even though real Python reaches the attribute mutation. An unsafe/dormant target pair should distinguish this from legitimate target-local shadowing. The bounded correction is actual bound Name targets only, preserving receiver/index expressions as reads; it is not a request for broader target precision.

2. **A nested merge can discard marked alternatives.** _merge_legacy_flow_values gathers only direct kind=generator operands (13742). If a previously merged marked pair is joined with a direct benign generator, the mixed branch at 13803–13812 retains only the direct generators' states. The earlier deferred_generator_merged operand is discarded. Its class flag does not set _FlowValue.sensitive, and _flow_is_sensitive does not inspect generator states (12537–12560), so the Boolean fallback need not preserve refusal. Two marked class generators can therefore be joined, then rejoined with an ordinary benign generator, before full consumption. This can be exercised inside the class body to avoid relying on the separate Q05 member carrier. Related wrapper issue: the fallback at 13814–13819 retains deferred_generator_container_merged alternatives, but _record_deferred_generator_consumption returns immediately for that wrapper kind (18204–18209), despite callers such as list accepting the recursive contains predicate (21302–21322). Preserve all alternatives/obligations through these routes; precise deferred evaluation is not required.

3. **The full-consumption sensitivity gate treats a changed empty iterator differently from direct next.** _deferred_generator_state_is_sensitive refuses a marked state only when remaining != 0 (18395), then permits remaining==0 with a changed mutable outer iterator to enter a probe over current caller values (18474–18510). _consume_generator_expression correctly includes outer_iterator_changed in its marker guard (18530–18538). Full/list/tuple and generator method paths use the sensitivity route. A class-created generator whose initially empty source later grows can thus consult a class/caller shadow instead of retaining its enclosing lexical dependency. This is a guard asymmetry, not proof that the ordinary empty-unchanged control should refuse. The new witness should preserve a genuinely dormant empty-unchanged control.

## Disposition

Q05 has a retained public unsafe-clean result with a concrete class-summary cause. The three further concerns need independently frozen cases before execution; their source mechanisms alone are not counted as extra runtime failures. The current eager projection architecture has useful scoped support, but the new deferred marker is not closed under all existing class/merge/container transformations or reached-consumer paths. Fixing only the two explicit marker checks cannot establish that closure.
