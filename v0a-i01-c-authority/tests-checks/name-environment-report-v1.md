## Reuse boundary and engineering implication

The concrete repeated-work mechanism is full name-map copying and full projected-name normalization across successor work, even when ambient names do not change. A versioned name environment may reduce those visits, but the required semantic outcomes stay independent of that design. Preserve the issued24 source schedules,58 oracle projections and explicit refusal labels when evaluating a replacement. Track actual physical work in the new implementation; do not count every operation named copy as N physical visits if it becomes a shared O(1) fork. The current observer is deliberately pinned to v19 and must not be blindly reused under a changed representation.

This family does not prove an overall complexity bound, demand zero copying everywhere, specify internal storage fields, measure wall time, or replace the real-corpus budget gate. It does not attribute every copied name solely to the C change: the observed v19 path includes inherited analyzer behavior. The useful requirement is to remove the demonstrated repeated work while preserving public contracts and original accounting/caps, then rerun ordinary generation in the proper lane. Root owns that architecture/implementation decision.
