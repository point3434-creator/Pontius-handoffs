## Structural measurement and RED predicate

The structural target is repeated work over unchanged ambient bindings as source alternatives grow with D=0. The observer is pinned to v19 code, not a requirement on a future representation. It will call all wrapped originals unchanged and retain scalar counters only:

1. At _ExecutionState.copy14176-14181, count calls, total len(self) copied entries and ambient-key copied entries. Source inspection proves v19 performs dict.__init__(result,self), so these are physical name-entry copy visits at that boundary. The observer may enumerate the small key set to classify ambient names; this extra diagnostic enumeration is not charged production work. These are a lower bound over this selected copy boundary, not every raw name copy in the analyzer. A future O(1) fork must not be mislabeled a physical copy merely because its API name remains copy.
2. At direct _merge_flow_values calls from _merge_states, count projected-name normalization calls and input operand visits, including a separate ambient_ subset. This records actual repeated merge normalization at that source boundary. It does not infer visits from the caller's own planner representation and does not count recursive helper-value merges as projected-name normalization.
3. At _AnalysisBudget.consume, count actual requested units, calls, largest observed per-budget work counter, caller/parent totals and any original exception. Delegate original code and leave all5 caps unchanged. Sum across budgets and maximum individual budget are distinct; physical copy counters are never added to charged units.

For each N=8/64 and exit=normal/exceptional, compare S=2 to S=4 at D=0. Report every pair. Structural repeated-work RED means a pair has increased physical ambient-copy visits and/or increased ambient merge-normalization visits/operands as S grows, with visits exceeding one touch per immutable ambient binding; public semantic outcomes must be assessed separately and must not change the fixed expectation. The report must state exactly which dimension demonstrates RED, not require every case to fail or overclaim a general complexity proof. D=2 pairs are fixed-small-change controls. N=8 versus64 comparisons show ambient-size dependence at fixed S,D,exit. No wall-time threshold, new budget, required storage data structure, cache field or universal zero-copy promise is introduced.

The pre-existing real-corpus --write budget RED remains separate evidence. This small family is intended to expose the structural amplification without giant payloads or demands for a fresh public false negative. Any semantic blocker/row mismatch, syntax/oracle error, or original budget failure is a separately labeled result, not evidence that the structural assertion passed. If a family fails to exercise its intended boundary, report that limitation without retrofitting its expectations.
