## Required R2 semantic addition

Current R1 honestly refuses unknown truth. Supporting this benchmark is therefore an R2 design addition, not a correction of an R1 scalar promise.

The smallest addition is a distinct internal fact for a proved builtin-boolean result whose value remains unknown, produced by supported identity comparisons after their operands have completed. Its producer proof is the identity operation itself. A normal branch on that fact can produce true and false successors using existing owned-state forks and tagged outcomes. Known literal booleans still specialize normally. A generic unknown value, rich comparison result or reason string must never acquire that proof implicitly.

For this simple ladder, three binary decisions along the false-prefix path yield four feasible terminal regions. No finite-domain API, user-provided assumption, fixture-ID rule, field-name rule or constant substitution is needed. More general repeated-predicate correlation can remain conservatively imprecise; this proposal does not introduce a general constraint solver or broaden the class heap.

Known exception construction/routing and negative scalar literals required by D2 remain separate R2 mechanisms. Generator70/depth support likewise is not solved by this premise repair.

## Why not an input-domain API now

A public finite-domain API could retain integer equality only if it supplied and bound a real exact-type premise, distinguished source/receiver ownership, validated it, included it in immutable evidence and admitted all alternatives in one analysis. It would change the public analysis contract and require a new caller/manifest/control path. Four harmless integer Models alone still would not supply that premise.

That API is proportionate if real users need conditional analysis under declared input assumptions. It is unnecessary for this four-region cost question: identity predicates already have the required language-level safety property for arbitrary values. Choose it later only as a deliberate product feature, not a hidden benchmark escape hatch.

No performance improvement is predicted. This proposal repairs the prospective premise and identifies how to distinguish actual branch/join work from a superficially clean output.
