# V25 v3 origin clarification

Engineering-only normative companion to engineer-generator-v25-semantic-plan-v3.md,
SHA256 1d661231a472fc689af06ea993234f27ab88a65da950d83f1811c1f941d94723.
No source import, payload or witness execution accompanies this document.

Root explicitly accepted the v3 enabled reservation and narrow unresolved-origin
fallback after v3 was issued. The fallback is now authorized; the earlier pending
sentence is superseded. No broader heap or positive class precision is authorized.

Recognition is structural and current-state based. A class_member_owner=True
record is created only by the enabled normal class-completion reserve boundary.
An explicit implicit_class alternative, including one reached through a result
alternative carrier or an existing untagged record, lacks proved transport
ownership when no live tagged class-owner record covers that alternative.
This includes an ordinary transfer of a disabled-origin class projection: merely
registering helper metadata later cannot mint the normal-construction tag.
Missing and mixed alternatives remain unresolved. An opaque value with no class
alternative is not guessed to be a class from its name, source line, scalar
contents, descriptor equality or unrelated captured/contained object.

The owner resolver returns both ordered live owner IDs and unresolved-class
evidence. It must not discard a missing alternative because another is tagged.
It follows only receiver alternatives; ordinary contained elements and callable
captures are not receivers. Class-instance lookup can retain a class read edge,
but an instance write is not silently redirected into the class owner.

_retain_class_member_write receives the original site. It transfers incoming
roots and retains them on reachable current tagged records under name/wildcard.
If an explicit class alternative has unresolved ownership AND the supplied value
contains retained callable or deferred may-roots, it emits a typed unsupported
namespace-store refusal at that site, using the existing helper namespace
refusal channel. The refusal survives enclosing helper completion and prevents
a later clean authorization even when the missing record cannot hold the roots.
Reachable existing records keep their incoming/old may-roots; no alias identity
is fabricated. The origin test does not depend on whether a deferred body is
currently sensitive; even an empty generator's origin must not be laundered.

This is a NEW conservative store boundary for unresolved class origin, and an
explicit exception to the earlier blanket dormant-store sentence. Enabled
reserved classes keep dormant marked storage unrefused. Scalar and other values
without callable/deferred obligations do not trigger this new fallback.
Deletion adds no incoming root and preserves existing guards/may-roots.
There is no new blanket refusal for ordinary global/imported-name reads.

Every owner/root/alternative visit, dedup/copy and new allocation uses the
existing operation budget. The existing AuthorityRecord identity fast paths
avoid implicit traversal of the new metadata. Original 44 labels stay fixed;
the independent later-store witnesses remain separately owned by the reviewer.
